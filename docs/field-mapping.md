# Export and API Field Mapping

## 自动契约

`apps/collector/src/tzzb/export-contract.ts` 固化了官方导出的 27 个持仓表头及来源类型，CI 会检查顺序、数量和 5 个源数据空字段。真实导出文件不进入 Git；当官方格式变化时，应先在本机重新检查工作簿，再更新契约与测试。

## 当前持仓

当前导出持仓包含 27 列。实际有值的字段可以由以下数据组合得到：

- 基础持仓：代码、名称、数量、成本、持仓天数、基础盈亏、周期盈亏。
- 最新行情：最新价、昨收、最新涨幅。
- 当日成交：买卖数量、价格和费用。
- 资金变化：转入转出及期初资产修正。
- 前端计算：当日盈亏、仓位、累计盈亏、回本涨幅和周期涨幅。

股票账户中当前为空的列：关联板块、板块涨幅、组合盈亏、组合涨幅、累计盈亏率。采集器应保留可空语义，不要伪造数值。

当前标准化器已经覆盖：代码、名称、持有金额、当日盈亏/率、持有盈亏/率、累计盈亏、周/月/年盈亏、仓位、数量、天数、最新涨幅/价格、成本、回本涨幅和近 1/3/6/12 月涨幅。上述 5 个空字段明确写入 `null`。

比例字段默认按同花顺当前网页的“百分数单位”转换为内部小数；若真实响应验证显示某账户返回小数单位，可通过 `TZZB_RATE_UNIT=decimal` 切换，禁止依靠数值大小猜测。

## 已清仓

使用 `cleared_position` 数据形成：清仓日期、代码、名称、总盈亏、盈亏比、同期大盘、跑赢大盘、买入均价、卖出均价、清仓距今、持仓天数、交易费用和建仓日期。

## 交易记录

使用分页历史接口形成：成交日期、成交时间、代码、名称、交易类别、成交数量、成交价格、发生金额、成交金额、费用和备注。

分页请求必须持续到服务端返回的最后一页，并校验总记录数。

完整历史与清仓分页属于下一实现批次；当前 Collector 只拉取生成“最新持仓快照”所需的当日成交与资金变化，不会把单日请求冒充完整历史。
