# Agent Design

## 设计原则

Agent 的第一职责是准确整理事实，而不是预测市场。所有输出遵守：

1. 先验证数据新鲜度，再分析持仓。
2. 结论必须引用快照、持仓或计算证据。
3. 规则计算与自然语言解释分离，便于测试和审计。
4. 每次运行保留 `snapshotId`、时间、状态、模型标识和证据。
5. 不把风险线索包装成确定性买卖建议，不调用交易能力。

## 当前分析

- 数据源超过阈值未同步时优先提示。
- 单一持仓超过关注/风险阈值时提示集中度。
- 现金占比低于阈值时提示流动性事实。

这些规则位于 `packages/agent-core`，可被 API、客户端演示模式和自动任务共同复用。

## 未来扩展

- 相邻快照差异：新增、加仓、减仓、清仓。
- 行业集中度、相关性与账户合并视角。
- 将新闻或公告作为带时间戳的外部证据，但与持仓事实分层展示。
- 通知策略：只发送新增或显著变化的观察，支持免打扰与频率限制。
- 模型解释：只能基于已登记证据生成摘要，输出仍通过结构化契约校验。
